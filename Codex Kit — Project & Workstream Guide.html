Project setup
& launch

1
Setup

Install or maintain Codex Kit’s managed machine integration.

  • Install or upgrade the Kit
  • Check current machine setup
  • Repair managed files safely
  • Uninstall when appropriate
2
Bootstrap

Build or refresh the shared understanding of a project.

  • Supports greenfield and brownfield projects
  • Looks for existing documentation and repository context
  • Forms an initial view of the project’s purpose
  • Starts an intake conversation when more context is needed
  • Re-run after a Kit upgrade when guidance needs updating
3
Commission

Create the Project Lead once the project’s guidance is ready.

  • Creates one user-visible Project Lead
  • Gives it the project context and role
  • Codex Kit pins it automatically
  • The user does not need to pin it
4
Launch

Create a new workstream from the Project Lead.

  • Describe the goal or point to the Jira item
  • The lead prepares a launch / briefing packet
  • Project background travels with the workstream as needed
  • Use /plan mode in the workstream and approve a plan before implementation

Project Lead responsibilities

Bootstrap gives the Project Lead a view of the project’s goals and context. It acts as the launch point for workstreams, using that whole-project perspective to provide relevant background in each launch packet.

“Codex Kit pins the Project Lead automatically. Commission creates and pins it; the user does not need to do this.”

What counts as a workstream?

↗

“A workstream corresponds to an independent Jira item: a bug, story, and usually, an epic. Subtasks are not intended to be workstreams.”

Describe the workstream goal, or point to a Jira ticket. The Project Lead prepares a launch / briefing packet and starts the workstream with the relevant project background.

Role selection by work type

☾

Luna

Use as a spawned executor for bounded work with a complete packet and clear stop conditions.

  • Low/medium: file inventories, evidence collection, deterministic commands, focused tool/API calls
  • Medium: focused read-only exploration and mechanical changes
  • High: bounded execution from an approved plan
  • Max: long, fully specified execution with strong checks
▲

Terra

Use as a spawned executor, fresh reviewer, or fresh verifier when the selected lane requires it.

  • Medium: normal execution or remediation; fresh review for small work
  • High: complex execution or remediation; fresh review for normal work
  • Low/medium: fresh focused verification
  • Also selected as Workstream Lead for small through normal work
✦

Sol

Use when independent scrutiny or exceptional judgment is materially valuable.

  • High, read-only: fresh review for protected, high-risk, or difficult-integration mutations
  • XHigh/Max: exceptional advice
  • Selected as Workstream Lead for protected, architecture-heavy, high-risk, or difficult integration
  • Reviewer never implements findings
